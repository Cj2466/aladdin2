Aladdin2 — technical reference

A personal-scale research pipeline built like a quant desk, not a stock-picking app

Discover signals across 503 tickers, backtest them honestly, correct for the bias of testing thousands of configurations, track survivors against real un-gameable time, then (planned) combine and trade the ones that hold up. This document is the system as it actually stands today — what's running, what's designed, what's still ahead.

01 Overview

Every layer exists to answer one question honestly: has this specific trade actually earned trust, or does it just look good because we haven't checked hard enough yet?

  • Not one model. No neural net, no single trained predictor. A systematic pipeline that discovers many small, statistically distinct trading rules — closer to how Renaissance's own research process is described than to a single "the algorithm."
  • Honesty is load-bearing, not decorative. Every backtest carries its own deflated Sharpe ratio, discounted by how many similar configurations were tried before it. A result that looks good on trial #1 and a result that looks identical on trial #500 are never shown as equivalent.
  • Two kinds of evidence, never conflated. A backtest replays history. Forward validation tracks a strategy one real trading day at a time, starting from today — it cannot be gamed, sped up, or re-run on a friendlier window. 126 real trading days is the threshold where the second kind of evidence starts to count.
  • Runs itself. Background workers discover, backtest, and (once Phase 3.5 ships) register candidates every weekday with nobody logged in — the difference between a tool you operate and a system that compounds evidence on its own.

05 Backend service layers

Organized by directory under app/services/. Each layer is deliberately reusable across contexts — the same risk math serves both the ticker-based and strategy-based portfolio features; the same retry/backoff shape covers both the market-data provider and (planned) the broker client.

research_lab/

  • engine.py — the strategy-agnostic walk-forward core
  • ou_pairs.py / momentum.py — the two strategy families
  • screening.py / regime.py — universe scan, variance-ratio regime tag
  • deflated_sharpe.py — multiple-comparisons correction
  • strategy_registry.py — the per-strategy adapter seam

risk/

  • engine.py — correlation, VaR/CVaR, HHI, beta, volatility
  • optimizer.py — SLSQP mean-variance max-Sharpe
  • var.py / diversification.py / beta.py — the individual metrics
  • stress.py / factor_model.py — scenario & factor exposure

market_data/

  • yfinance_provider.py — retry/backoff-hardened fetch
  • price_cache.py — read-through cache, trading-calendar-aware
  • base.py — the provider interface a second source could plug into

07 Frontend

No client-side router — a lifted view-state toggle (DeepLinkGate / AuthGate) switches between the dashboard and the Research Lab page, matching this app's deliberately minimal-dependency style.

Dashboard

Portfolio risk analytics — build a ticker+weight portfolio, see volatility, beta, VaR/CVaR, HHI, correlation heatmap, mean-variance optimizer, stress scenarios.

Research Lab

Screening panel, single-backtest and sweep panels (pairs + momentum), the shared leaderboard with deflated-Sharpe breakdown, forward-validation tracker — and, once built, the strategy-portfolio and execution-control panels.

09 Roadmap status

Build order for what's not yet shipped: 3.5 → 4 → 5, in that sequence — each depends on the one before it.

PhaseWhat it is
0 – 3Walk-forward engine, forward validation, sweep automation + leaderboard, momentum strategy, universe screening, regime tagging, deflated Sharpe ratio, 503-ticker autonomous daily research, retry-hardened data fetchingshipped
3.5Auto-register discovered candidates for forward validation — the last automation gap; currently only 3 registrations exist with 1 tracked day each, and nothing feeds that number without thisin progress
4Combine several validated strategies into one risk-balanced portfolio — reuses the existing risk engine and optimizer against strategy return seriesdesigned
5Paper-trade the live portfolio through a real broker (Alpaca) — kill switch, daily-loss breaker, hard position caps, fail-closed by construction. Real capital only after paper trading proves itself, and only as a deliberate later decisiondesigned

What this system deliberately does not claim. It doesn't replicate Medallion's actual methods — nobody outside Renaissance knows them, and the document that prompted this write-up says so itself. It pursues the same discipline at a scale that's honestly achievable: real statistical correction for overfitting, real forward-time evidence, real risk budgeting — without HFT infrastructure that a daily-bar strategy gets no benefit from anyway.
