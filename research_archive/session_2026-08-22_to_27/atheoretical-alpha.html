Atheoretical Alpha

สองสายการค้นคว้า: (1) ใครในโลกที่พยายามเดินตามแนวทาง Renaissance Technologies / Medallion Fund โดยตรง — สถิติล้วน ไม่อิงทฤษฎีเศรษฐศาสตร์ (2) ภูมิทัศน์ที่กว้างกว่านั้น — งานวิจัยและผู้ปฏิบัติทั่วโลก ที่มีเป้าหมายคล้ายกันแต่เดินคนละเส้นทาง ทุกข้อความมาจากแหล่งข้อมูลจริงที่ตรวจสอบแล้ว พร้อมระบุระดับความเชื่อมั่นกำกับไว้ทุกข้อ

รอยตาม Medallion โดยตรง

ข้อค้นพบหลัก: คนที่ "ตั้งใจเลียนแบบ Medallion" ตรงๆ และมีหลักฐานยืนยันได้จริง มีน้อยกว่าที่เชื่อกันทั่วไปมาก รูปแบบที่พบบ่อยที่สุดคือ วิวัฒนาการคู่ขนาน — หลายบริษัทมาถึงปรัชญา "สถิติล้วน ไม่อิงเรื่องเล่าพื้นฐาน" ด้วยตัวเอง ไม่ใช่การก็อปปี้ Renaissance

ไม่ใช่คนนอกที่มาเลียนแบบ แต่เป็นผู้ร่วมออกแบบตัวจริง — ซื้อหุ้นใหญ่ใน Axcom (บริษัทก่อน Medallion) ปี 1989 ปรับอัลกอริทึมใหม่รอบสัญญาณผิดปกติระยะสั้นที่ทีมเรียกว่า "ghosts" ทำกำไรสุทธิ 55.9% ในปี 1990 ก่อนขายหุ้นคืนให้ Simons

"สร้าง Medallion ฉบับตัวเอง" ระดับบุคคลไม่พบหลักฐาน

ค้นพบงานเขียนอธิบายเรื่องราว Renaissance จำนวนมาก (ซีรีส์ 3 ตอนของ Branko Blagojevic บน Medium, บล็อก danielscrivner.com) แต่ ไม่พบบล็อกเกอร์ นักวิจัยอิสระ repository บน GitHub หรืองานวิชาการชิ้นใดเลย ที่บันทึกความพยายามจริงจังในการสร้างระบบ pattern-mining แบบ atheoretical โดยอ้างอิง Medallion เป็นเกณฑ์เทียบ พร้อมผลลัพธ์จริง — ดูเหมือนเป็นช่องว่างจริง ไม่ใช่ปัญหาการค้นหา เพราะความลับสุดยอดของ RenTec คงทำให้แทบไม่มีใครกล้าเขียนแบบนั้น

ภูมิทัศน์ที่กว้างกว่า

ไม่จำกัดแค่คนที่อ้างอิง Medallion — นี่คือโลกทั้งใบของงานวิจัยและผู้ปฏิบัติที่เดินหาเป้าหมายเดียวกัน (ค้นหา pattern ทางสถิติล้วน ไม่อิงเรื่องเล่าเศรษฐศาสตร์ พร้อมวินัยป้องกัน overfitting) ด้วยวิธีที่ต่างออกไปโดยสิ้นเชิง

Point of tension

López de Prado เองก็ไม่เชื่อว่า backtest ล้วนๆ พิสูจน์อะไรได้

ผู้เขียน Deflated Sharpe Ratio ที่โปรเจกต์นี้ใช้เป็นแกนหลัก สรุปไว้ตรงๆ ว่าการทดสอบย้อนหลังแบบ atheoretical ทำได้แค่ หักล้าง กลยุทธ์ที่ไม่ดี ไม่สามารถ พิสูจน์ ว่ากลยุทธ์ใช้ได้จริง และแนะนำให้ผูกกับทฤษฎีที่ทดสอบได้บ้าง — นี่คือจุดตึงจริงกับแนวทาง "ไม่อิงเศรษฐศาสตร์เลยเพราะมนุษย์มีอคติ" ที่วางไว้ตั้งแต่ต้น ไม่ได้แปลว่าแนวทางเดิมผิด แต่ควรรู้ไว้ว่าคนที่คิดค้นเครื่องมือหลักที่ใช้อยู่ มีความเห็นต่างในจุดนี้

Combinatorial Purged Cross-Validation (CPCV) — เทคนิคที่ Phase 3.6 เคยพิจารณาแล้วปฏิเสธเพราะ engine ปัจจุบันไม่มีช่องโหว่ที่ CPCV แก้ — มี implementation จริงอยู่แล้วใน mlfinlab หากอนาคตมีสถาปัตยกรรมที่ overlapping fit window กลายเป็นปัญหาจริง (ต่างจากตอนนี้) นี่คือจุดเริ่มที่ตรวจสอบไขว้ได้ก่อนสร้างเอง

รวบรวมโดย 2 research agent · WebSearch/WebFetch สดในวันที่รายงาน ไม่มีชื่อ ผู้แต่ง หรือข้อเท็จจริงใดถูกสมมติขึ้น — ระบุ "ไม่พบหลักฐาน" ตรงๆ เมื่อค้นไม่พบ
