1a. github.com/rkohli3/TSMOM -- "Replication of Time Series Momentum strategy by Moskowitz, Ooi,
    Pedersen, 2011" -- THE MOST SUBSTANTIVE LEAD FOUND, CHECKED IN FULL, STILL A DEAD END
----------------------------------------------------------------------------------------------------
  Repo tree fetched live via the GitHub API (api.github.com/repos/rkohli3/TSMOM/git/trees/master).
  Contains data/futures.csv (4.74 MB), data/futures_list.csv (metadata), data/spy_1985.csv. Both CSVs
  downloaded and parsed directly (not just described from the README).

  CONTENT, VERIFIED BY ACTUALLY PARSING THE FILE:
    - futures_list.csv lists 55 instruments across bonds/currencies/equity-indexes/commodities,
      INCLUDING all three target ICE softs: CT=Cotton, KC=Coffee, SB=Sugar No. 11.
    - futures.csv is DAILY RETURNS (not price levels), one row per trading day, 8,474 rows,
      1984-01-03 to 2016-10-28 (parsed directly: first date 1/3/84, last date 10/31/16, though the
      final row for every column including KC/SB/CT is empty -- true last populated date for all
      three is 2016-10-28). KC has 8,175 non-empty rows, SB 8,194, CT 8,241 out of 8,474 possible
      trading days -- a real, mostly-complete daily series, not a sparse/placeholder one.

  PROVENANCE CHECK -- THE README'S OWN CLAIMED SOURCE DOES NOT MATCH THE DATA:
    The README states data.py downloads prices "via yfinance" (Yahoo Finance) -- but yfinance's
    futures history does not reach back to 1984 for any of these instruments, and futures.csv is a
    pre-existing static file in the repo, not something data.py's live-download path would produce.
    The real origin of futures.csv is UNSTATED anywhere in the repo (no data dictionary, no source
    citation in the CSV header or README). This is disclosed honestly as unresolved, not glossed
    over -- the data is plausibly from an institutional/terminal source (e.g. Bloomberg or a similar
    proprietary feed) redistributed without attribution, which is itself a licensing red flag on top
    of the explicit absence below.

  CROSS-CHECK PERFORMED (real, not claimed): fetched EIA's live RCLC1 (WTI front-month) page fresh in
  this session (https://www.eia.gov/dnav/pet/hist/RCLC1d.htm, via this project's own already-audited
  eia_nymex_futures.parse_weekly_html()), computed EIA-implied daily returns for Jan-Feb 2015, and
  compared them to futures.csv's CL column for the same dates:
    2015-01-05: TSMOM -0.050245 vs EIA-derived -0.050294 (diff 0.00005)
    2015-01-06: TSMOM -0.042222 vs EIA-derived -0.042166 (diff 0.00006)
    2015-01-14: TSMOM  0.056453 vs EIA-derived  0.056439 (diff 0.00001)
    2015-01-16: TSMOM  0.052753 vs EIA-derived  0.052757 (diff 0.00000)
    2015-01-21: TSMOM  0.028191 vs EIA-derived  0.029963 (diff 0.00177, the largest of the sample)
  15 dates compared in Jan 2015; all but one matched to within ~0.0002 (2 basis points), consistent
  with genuine WTI-linked daily return data (not fabricated), with the single larger divergence on
  2015-01-21 plausibly explained by a differing roll-date convention between the two series (EIA's
  positional C1 vs whatever continuous-roll rule produced futures.csv) -- not chased further given
  the disqualifications below make the point moot. This is real evidence the CL column is genuine
  market data, not proof about the KC/SB/CT columns specifically (no independent ground truth for
  those three exists in this project to cross-check against, which is the whole reason this search
  was run).

  WHY THIS IS STILL A DEAD END, EVEN THOUGH THE DATA LOOKS REAL:
    1. NO LICENSE. Checked the full repo tree via the GitHub API for any LICENSE/LICENCE file --
       none exists. No SPDX header, no README license section. Under default copyright, this is
       "all rights reserved" by the repo owner (who, per the provenance problem above, may not even
       be the rights holder of the underlying data). This alone fails the usability gate outright,
       independent of every other finding below.
    2. Returns only, not settlement price levels -- would need reconstruction from an anchor price
       (which the repo does not provide) before it could serve as a per-contract-equivalent series,
       and even then it is a continuous/rolled series (unknown roll rule, not disclosed anywhere in
       the repo), which would need its own PROOF_1/2/3 treatment -- moot given point 1.
    3. Ends 2016-10-28. Does not touch gap (b) (2025-09-13-to-present) at all. For gap (a)
       (KC/SB/CT), it would at best extend history back into 1984-2016 IF the license and roll-rule
       problems were somehow resolved -- neither is resolvable from what this repo provides.
  VERDICT: DEAD END. Real-looking data, well short of usable on licence grounds alone, and even
  setting licence aside, addresses neither gap as scoped.
