## Notes on what a plain `curl` gets you vs. what needed a headless browser

- The **delisted-securities list page** is Nuxt SSR: the static HTML shell fetches
  fine (200) but the 346-row table is populated by a client-side call this agent
  could not identify from the static bundle (no `/api/...` path string found in
  the inlined `__NUXT__` payload or any linked JS chunk within the time budget).
  A headless browser (`browser-automation` skill, patchright/Playwright) was used
  instead: it rendered the page, and the full 346-row table appeared directly in
  the accessibility tree with no extra network calls needed on this agent's part
  -- pagination was driven by clicking the page-number controls (18 pages x 20
  rows), not by discovering a JSON endpoint. This matches the review's finding
  that `set.or.th`'s *JSON* endpoints 403 a plain script -- the HTML page itself
  is not blocked, it is just SSR + client-hydrated.
- The four **market-statistics pages** (investor-type, NVDR-by-stock,
  short-sales, program-trading) are ALSO Nuxt SSR, but unlike the delisted list,
  `curl`'s static fetch of these returns HTTP 200 with only the page chrome --
  the actual tables require JS execution and were read via the headless browser
  (see `m3_set_daily_files.md` for what was found and the exact interaction
  attempts, including which UI controls were and were not operable
  programmatically within the time budget).
