# SECTION 0 -- THIS IS NOT A BLIND PRE-REGISTRATION. READ THIS FIRST.
################################################################################

Every other pre-registration in this project locks a spec before its result
exists. THIS ONE DOES NOT, and saying otherwise would be exactly the kind of
false precision CLAUDE.md's zero-fabrication rule exists to prevent.

THE FACTS, PLAINLY:

1. The immediately-prior task (merged to main as f0cd8e1, branch
   tsmom-idio-signal) tested the FACTOR-HEDGED idiosyncratic TSMOM as its
   candidate. It built the plain UNHEDGED MOP TSMOM only as a reference/control
   leg -- explicitly, so that the hedge's effect was measurable and so that a
   grid of near-identical specs would not produce a degenerate sigma_SR.

2. That control leg's 12-block spec scored, on main, in a committed and
   already-read report and JSON:
        gross Sharpe +0.8176   net Sharpe +0.6796
   These exact numbers are visible today at
        backend/data/research_runs/tsmom_idiosyncratic_signal_2026-09-08.json
        -> specs.lb12_unhedged
   and the prior task's own memory note called it "the strongest raw number
   this entire research thread has produced".

3. THE FACT THAT THIS NUMBER LOOKED GOOD IS THE ENTIRE REASON THIS FOLLOW-UP
   FAMILY IS BEING BUILT. The project owner asked for it specifically because
   +0.68 net was already on the table. There is no version of this task in
   which the spec was chosen before the result was seen.

4. Therefore this document is a PRE-REGISTRATION OF THE ANALYSIS ONLY (what
   will be computed, at what bar, with what verdict rule, with no further spec
   search), layered on top of an ALREADY-OBSERVED result. It is a
   second-look/selected-spec confirmation, not a fresh test.

WHY THIS MATTERS STATISTICALLY, NOT JUST RHETORICALLY:

The DSR ladder's most lenient rung, n_local, encodes the assumption "this
family is a small, honest, self-contained search and the deflation only needs
to cover its own grid." That assumption is FALSE HERE. The spec being reported
was picked out BECAUSE it was the best-looking leg among the six specs already
run, and it was the best-looking leg of a thread that has been searching this
same futures panel for roughly four days across breadth gates, factor
decompositions, bias quantifications and a hedged candidate. Deflating by
n_local=3 (or 6) would be correcting for a search far smaller than the one that
actually produced this spec -- an anti-conservative error of exactly the kind
the ladder exists to prevent.

SPEC GRID -- reused exactly, nothing added, nothing swept:
  lookback horizon in 21-trading-day blocks: {1, 3, 12}, unhedged only.
  Grounded in MOP (2012) horizons and Hurst/Ooi/Pedersen (2013)'s 1/3/12-month
  diversified set. No other horizon screened, no new dimension introduced.
  These are the SAME THREE unhedged legs already computed on main; the numbers
  are expected to REPRODUCE main's exactly. Reproduction is the point --
  the job is to subject that same object to full family treatment, not to find
  a better spec.

HEADLINE SPEC: lookback = 12 blocks, unhedged, cost anchor 2.5%/yr.
  MOP 2012 p.236: "we focus on the properties of the 12-month time series
  momentum strategy with a 1-month holding period (e.g., k=12 and h=1), which
  we refer to simply as TSMOM". Also the already-seen spec -- see Section 0.

DATA: identical panel and window to main's run. NOTE A CORRECTION TO THE TASK
BRIEF'S PHRASING: the RAW CME SPAN panel spans 2013-01-02..2025-09-12, but the
COMMON window (dropna how=any across all 31 instruments) is
2017-07-10..2025-09-12 (2127 obs), and after the 504-day burn-in the strategy
return series runs 2019-06-18..2025-09-12 (1623 days). The shorter effective
window is what was actually used before and is what is reused; it is stated
here rather than repeating the raw-span dates as if they were the test window.
1623 days is ~6.4 years and is itself a limitation on any verdict.

COST MODEL: reused verbatim from main's script, including the CORRECTED
turnover-matched calibration (the reference leg is the 252-day unhedged leg
rebalanced WEEKLY, matching Hurst et al. Section 3.1's Friday-close rebalance;
back-solving from the 21-day book's lower turnover was the calibration mistake
caught last time and is retained only as a labelled over-punitive
sensitivity). Citation: Hurst, Ooi & Pedersen (2013), "Demystifying Managed
Futures", Journal of Investment Management 11(3), 42-58, Section 5 p.55 (1-4%
annual costs, sophisticated trader; footnote 7, ~USD 1bn AUM; reference book
run at 10% annualized volatility). The back-solved c does not depend on the
spec grid, so it is bit-identical to main's.

sigma_SR JUDGMENT CALL, DECLARED IN ADVANCE: as its own family the grid is 3
unhedged specs, so the family-local sigma_SR is the std (ddof=1) of those 3
net Sharpes and n_local = 3. Main's run used 6 specs (sigma_SR 0.3376871). BOTH
are reported: the 3-spec version as this family's own, the 6-spec version as
the exact reproduction of main. Neither is the verdict rung (Section 1), which
is precisely why this ambiguity is allowed to stand rather than being resolved
by picking whichever is more favourable.
